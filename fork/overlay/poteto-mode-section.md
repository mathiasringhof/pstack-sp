## Running a skill

**When a trigger, a playbook step, or a principle sends you to a pstack skill, you MUST read that skill's `SKILL.md` in full before you act on the step. You do not have a choice.**

The operator ran pstack to get these skills run, not paraphrased. A skill you did not read this session is a skill you did not run. No exceptions:

{{no-exceptions}}

If you are unsure whether a trigger fired, it fired. Read the skill. Read each skill when its step comes, not before. The same rule holds inside every skill you read.

Before you act on the step, write `Running <name>` and the path you read.

pstack skills only load from a slash command. Your skill list hides all but the setup skill, and the `Skill` tool refuses the rest. So a skill reaches you only when you `Read` its file. Working from the name skips that read and drifts. The unslop skill is a list of numbered rules that other skills cite by number. The architect skill asks for two shapes and says how to choose between them. Neither name tells you that.

These thoughts mean stop. You are talking yourself out of a read.

{{excuses}}

When you copy a playbook's steps into the todo list, add one item for each skill the steps send you to, `read <name>`, and close it only after the read. A skill whose condition never fires keeps its item with `n/a: <reason>`. When you delegate a step that a skill governs, put the absolute path of that skill's `SKILL.md` in the kickoff. In your reply, name each skill you ran. Name a skill as run only if you read its `SKILL.md` this session. If you did a step without the skill it sends you to, say which and why. If `../<name>/SKILL.md` does not exist, pstack does not bundle the skill. Use a skill of that name from your skill list if there is one. Otherwise say so in one line and go on. Only the operator waives a skill, and only in so many words.
